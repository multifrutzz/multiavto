# multiavto

Практические работы № 1–4 по интернет-технологиям.
Вариант № 11 — магазин автомобилей.

Учебный сайт для подбора и сравнения автомобилей.
Цены, пробеги и контактные данные используются для демонстрации.

## Запуск на macOS

Требуется Python 3.11 или новее.
В данном проекте окружение создано с Python 3.14.

Команды выполняются из основной папки проекта, где находится main.py.

При первой настройке:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Если окружение и библиотеки уже установлены:

```bash
source .venv/bin/activate
python -m uvicorn main:app --reload
```

Адрес сайта: http://127.0.0.1:8000/

Остановка сервера: Control + C в терминале.

Сайт нужно открывать через сервер, а не двойным нажатием на HTML-файл.
Во время проверки входа используйте один адрес — 127.0.0.1.

При первом запуске создаются база data/multiavto.db и таблицы.
Если таблица cars пустая, в неё добавляются 15 машин из cars.json.
При следующих запусках аккаунты, сообщения и сравнения сохраняются.

Изменение cars.json после заполнения базы не обновляет записи в базе автоматически.

## Выполненные возможности

- Главная страница с шестью автомобилями.
- Каталог из 15 разных моделей автомобилей.
- Фильтрация по цене, году и пробегу.
- Сортировка по цене и году выпуска, сброс фильтров.
- Общая подробная страница car.html?id=номер.
- Главная, каталог и подробная страница получают машины с сервера.
- Курс доллара через внешний API и пересчёт цен.
- Регистрация, вход, профиль и выход.
- Личное сравнение с добавлением и удалением машин.
- Сохранение обращений из формы контактов.
- Проверка данных в браузере и на сервере.
- Сообщения о загрузке, ошибках и результате действий.

Исходные 12 машин дополнены BMW M4 Competition G82,
Bugatti Divo и Ferrari 812 Superfast.

## База данных

Используется SQLite. Внешние ключи включены для каждого подключения.

### users — пользователи

- id — INTEGER PRIMARY KEY, номер пользователя.
- name — TEXT NOT NULL, имя.
- email — TEXT NOT NULL UNIQUE, уникальная почта.
- password_hash — TEXT NOT NULL, хеш пароля Argon2id.

### cars — автомобили

- id — INTEGER PRIMARY KEY, номер автомобиля.
- name — TEXT NOT NULL, марка и модель.
- year — INTEGER NOT NULL, год не меньше 1900.
- mileage — INTEGER NOT NULL, неотрицательный пробег.
- body — TEXT NOT NULL, тип кузова.
- price — INTEGER NOT NULL, положительная цена в рублях.
- description — TEXT NOT NULL, описание.
- image — TEXT NOT NULL, путь к главной фотографии.
- image_alt — TEXT NOT NULL, описание главной фотографии.
- gallery — TEXT NOT NULL, список дополнительных фотографий в формате JSON.

### comparisons — выбранные автомобили

- user_id — INTEGER NOT NULL, внешний ключ на users.id.
- car_id — INTEGER NOT NULL, внешний ключ на cars.id.
- Пара (user_id, car_id) — составной первичный ключ.

Связь users и cars — многие ко многим через comparisons.
У пользователя может быть несколько машин в сравнении.
Одна машина может находиться в сравнении разных пользователей.
Повторное добавление той же машины не создаёт дубль.
При удалении пользователя или машины связанные записи удаляются
автоматически: ON DELETE CASCADE.

### sessions — сессии входа

- token_hash — TEXT PRIMARY KEY, SHA-256 случайного ключа сессии.
- user_id — INTEGER NOT NULL, внешний ключ на users.id,
  ON DELETE CASCADE.
- expires_at — INTEGER NOT NULL, срок окончания в секундах Unix.

Один пользователь может иметь несколько сессий.
Срок действия сессии — 24 часа.

### messages — обращения

- id — INTEGER PRIMARY KEY, номер сообщения.
- name — TEXT NOT NULL, имя отправителя.
- email — TEXT NOT NULL, почта отправителя.
- message — TEXT NOT NULL, текст сообщения.
- created_at — TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  время сохранения UTC.

Обращение может оставить гость, поэтому связь с users не требуется.
Сообщения сохраняются в базе, но не отправляются электронной почтой.

## API

- GET /api/cars — получить список автомобилей.
- GET /api/cars/{id} — получить один автомобиль по его номеру.
- POST /api/register — зарегистрировать пользователя.
- POST /api/login — войти в аккаунт.
- POST /api/logout — выйти из аккаунта.
- GET /api/me — получить данные текущего пользователя.
- GET /api/comparison — получить личный список сравнения.
- POST /api/comparison — добавить автомобиль в сравнение.
- DELETE /api/comparison/{id} — удалить автомобиль из сравнения.
- POST /api/messages — сохранить обращение из формы контактов.

Документация запросов: http://127.0.0.1:8000/docs

Профиль и операции сравнения доступны только после входа.
Пользователя определяет сервер по сессии.
Чужой список сравнения не возвращается.

## Проверка и хранение данных

Имя: 2–80 символов.
Почта: корректный адрес длиной до 254 символов.
Пароль: 8–128 символов.
Сообщение: 10–2000 символов.

Пароли хешируются готовой библиотекой pwdlib с Argon2id.
Открытые пароли в базе не сохраняются.
SHA-256 применяется только к случайным ключам сессий.

Ключ сессии хранится в cookie с HttpOnly и SameSite=Strict.
При выходе сервер удаляет сессию и cookie.

Переменные значения передаются в SQL через параметры ?,
без склейки пользовательского ввода с текстом запроса.

Файл базы с тестовыми аккаунтами не включается в репозиторий.
База и виртуальное окружение исключены через .gitignore.

## Внешний API

Источник курса: https://www.cbr-xml-daily.ru/daily_json.js

Курс загружается через fetch.
Показаны загрузка, дата курса и ошибка при недоступности источника.
Ожидание ограничено 10 секундами.
При ошибке курса рублёвые цены и фильтры загруженного каталога работают.

Для получения курса нужен доступ к внешнему сервису.
Каталог, аккаунты и сравнение используют сервер приложения и SQLite.
При локальном запуске эти функции работают без интернета.
Для доступа к опубликованному сайту интернет необходим.

## Проверка перед защитой

1. На главной шесть машин, в каталоге — 15.
2. Подробная страница показывает характеристики и пять фотографий.
3. Фильтры, сортировка и сброс работают без перезагрузки.
4. Ошибочные данные форм сопровождаются сообщениями.
5. Регистрация и вход работают; повторная почта отклоняется.
6. Сравнение сохраняется после обновления страницы и перезапуска сервера.
7. Машины можно удалять из сравнения.
8. После выхода личное сравнение недоступно.
9. У второго пользователя собственный список сравнения.
10. Корректное обращение сохраняется в messages.
11. На ширине 360 px страница не прокручивается вбок;
    широкая таблица прокручивается внутри своего блока.
12. База и файлы сервера не доступны для скачивания через сайт.

## Практическая работа № 4 — публикация сайта

Адрес сайта: https://multi.prod.page

Docker-образ: multifrutzz/multiavto:1.0.1

### Запуск через Docker Compose

1. Установить и запустить Docker Desktop.
2. Открыть терминал в папке проекта.
3. Создать файл .env по образцу .env.example:
    cp .env.example .env
4. Выполнить команду:

docker compose up -d --build

5. Открыть http://localhost в браузере.

Остановка приложения:

docker compose down

### Настройки

- SITE_ADDRESS — адрес сайта для Caddy при запуске через Compose.
- DATABASE_PATH — путь к файлу базы данных.
- COOKIE_SECURE — передача cookie только по HTTPS при значении 1.

Для локального запуска используются значения из .env.example.
На хостинге COOKIE_SECURE установлен в 1.

### Публикация

Приложение размещено на blitz.cloud из Docker-образа.
Хостинг обеспечивает HTTPS.
Папка /app/data подключена для постоянного хранения базы данных.

Проверено открытие сайта через мобильный интернет.
После перезапуска приложения автомобили в сравнении сохраняются.
